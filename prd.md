# Tropa — PRD

Локальное приложение «дорожная карта»: большая цель раскладывается на этапы, задачи и подзадачи, а Claude Code подключён к карте как к инструменту и правит её прямо во время работы.

- **Версия документа:** 1.0
- **Дата:** 2026-11-04
- **Автор карты:** один пользователь, работает локально
- **Статус:** готов к этапу 0

---

## 1. Зачем это нужно

Контекст в чате с ИИ заканчивается, проект — нет. Через несколько сессий агент забывает, что уже сделано, что осталось и почему принято то или иное решение. Каждый раз приходится объяснять заново.

Tropa — внешняя память проекта. Структура карты подогнана не под команду людей, а под агента: у задачи есть поля, которые нужны именно ему — что считать выполненным, что блокирует, какие файлы затрагиваются.

**Цель (что считается «сделано» для всего продукта):** Claude в начале сессии спрашивает карту «что дальше», делает задачу, отмечает её выполненной и дописывает, что всплыло по ходу — а пользователь видит это в браузере и правит руками.

## 2. Для кого

Один человек — автор. Новичок в технике, код руками не пишет и не читает: всё делает ИИ-агент, пользователь ставит задачи и проверяет результат. Отсюда требования: простой и предсказуемый стек, понятные ошибки, ничего, что требует ручной отладки.

## 3. Какие цели кладутся на карту

Любые, не только код:

- проекты с кодом — сайты, приложения
- околокодовые, где есть арт, тексты, релиз и модерация
- нетехнические — учёба, курсы, тренировки, переезд

Из этого следует: карта **не** привязана к папке проекта и **не** лежит в git. Поле «какие файлы трогать» — необязательное.

## 4. Главный сценарий

1. Пользователь пишет Claude: «цель — такая-то, вот вводные».
2. Claude через MCP создаёт карту: этапы, задачи внутри них, подзадачи, связи «что без чего не начать».
3. Пользователь открывает карту в браузере, смотрит, двигает ноды, правит формулировки.
4. Claude делает очередную задачу, сам отмечает её выполненной, добавляет новые подзадачи.
5. В следующей сессии Claude спрашивает «что дальше» и продолжает с нужного места.

Пункт 5 — ради чего всё затевается.

## 5. Модель данных

Четыре уровня: **Roadmap → Stage → Task → Subtask.** Глубже не идём: на пятом уровне карта перестаёт читаться глазами, а агент начинает плодить мусор вроде «открыть файл».

### Roadmap (карта)

| Поле | Тип | Зачем |
|---|---|---|
| id | строка | стабильный идентификатор, не меняется |
| title | строка | название карты |
| goal | текст | одна фраза: что считается «сделано» для всей карты |
| context | текст | вводные: ограничения, ссылки на материалы |
| archived | да/нет | убрана из активных |
| createdAt / updatedAt | дата | служебное |

### Stage (этап)

| Поле | Тип | Зачем |
|---|---|---|
| id, roadmapId | строка | связь с картой |
| title | строка | «M2 Экономика и данные» |
| order | число | порядок в сайдбаре |
| dependsOn | список id этапов | блокировки |
| color | строка | цвет группы нод на канвасе |

### Task (задача, нода на канвасе)

| Поле | Тип | Зачем |
|---|---|---|
| id, stageId | строка | связь с этапом |
| title | строка | заголовок карточки |
| description | markdown | что именно сделать |
| status | todo / in_progress / blocked / done | цвет и иконка карточки |
| acceptance | список строк | критерии приёмки — по ним агент понимает, когда закрывать |
| files | список путей, необязательно | какие файлы затрагивает (для кодовых целей) |
| dependsOn | список id задач | стрелки между нодами |
| estimate | число, необязательно | оценка в часах |
| x, y | числа | положение на канвасе |
| notes | лента записей | что реально сделано и на чём застряли; видно, где писал человек, а где агент |
| version | число | защита от одновременной правки |

### Subtask (подзадача)

Чеклист внутри задачи: id, taskId, title, done, order. Отсюда счётчик вида 10/36 в сайдбаре.

## 6. Где это хранится

Одна общая папка в домашней директории пользователя, по одному JSON-файлу на карту, плюс папка с автокопиями.

**Почему не внутри проекта и не в git:** у половины целей (учёба, тренировки, переезд) нет ни папки проекта, ни репозитория. Привязка к коду отрезала бы их.

**Почему файлы, а не база данных:** один пользователь и сотни задач — база выигрывает только на тысячах, зато приносит миграции при каждом изменении структуры. JSON читается глазами и чинится руками.

**Защита от потери:** перед каждой записью файл копируется в папку истории. Запись только через API, с проверкой структуры.

## 7. MCP-сервер: что получает Claude

Ядро всей затеи. MCP не трогает файл напрямую, а ходит через тот же API, что и браузер — иначе проверки и уведомления разойдутся между двумя реализациями.

### Чтение

| Инструмент | Что делает |
|---|---|
| list_roadmaps | все карты с прогрессом |
| get_roadmap | одна карта: этапы, задачи, связи |
| get_task | одна задача со всеми полями, подзадачами и заметками |
| get_next_task | **главный**: первая задача, у которой все зависимости закрыты |
| search_tasks | поиск по тексту, статусу или файлу |

### Запись

| Инструмент | Что делает |
|---|---|
| create_roadmap | новая карта с целью и вводными |
| bulk_create | целое дерево за один вызов |
| create_stage / create_task / create_subtask | точечное добавление |
| update_task | правка полей задачи |
| set_status | смена статуса; для blocked обязательна причина |
| toggle_subtask | галочка в чеклисте |
| add_note | дописать, что сделано или на чём застряли |
| link_tasks / unlink_tasks | связи между нодами |
| delete_* | удаление, только с явным подтверждением |

### Два правила важнее самого списка

1. **Позиции на канвасе агент не трогает.** Координаты ставит автораскладка или пользователь. Иначе после каждой сессии раскладка разъезжается.
2. **Ответы компактные.** get_roadmap на сотне задач отдаёт только заголовки, статусы и связи — без описаний и заметок. Подробности берутся через get_task. Иначе карта съест тот самый контекст, ради экономии которого делается.

## 8. Интерфейс

Один экран, три зоны.

**Сайдбар слева (~260px):** поиск по картам и этапам; список карт с кнопкой «+»; этапы активной карты со счётчиком и колечком прогресса; фильтр «Все / Активные / Готовые». Клик по этапу — канвас подлетает к его группе нод.

**Канвас в центре:** бесконечное полотно, зум колесом, панорамирование. Нода = задача: заголовок, полоска прогресса подзадач, цвет по статусу, рамка по цвету этапа. На близком зуме видно первые строки описания, на далёком — только цветной прямоугольник. Стрелки = зависимости, тянутся мышкой от края к краю. Миникарта в углу. Кнопка «Разложить автоматически».

**Панель задачи справа (по клику на ноду):** заголовок и статус; описание в markdown, правится по клику; чеклист подзадач; критерии приёмки; список файлов; лента заметок; блок «Блокируется / Блокирует»; кнопка «Скопировать промпт для Claude».

**Живое обновление:** когда Claude правит карту, вкладка обновляется сама за секунду-две, изменённая нода коротко подсвечивается. Без этого связка ощущается мёртвой.

## 9. Стек

| Часть | На чём | Почему |
|---|---|---|
| Интерфейс | React + Vite + TypeScript | больше всего примеров — агент реже ошибается |
| Канвас | React Flow | ноды, связи, зум и миникарта из коробки |
| Автораскладка | Dagre | стандартная пара к React Flow |
| Сервер | Node + Express | самая описанная библиотека; скорость не нужна, один пользователь на localhost |
| Живое обновление | SSE | нужен поток только в одну сторону, проще WebSocket |
| MCP | официальный SDK, транспорт stdio | простейший способ подключиться к Claude Code |
| Хранилище | JSON-файлы | читаемо, чинится руками, нет миграций |

Сервер слушает только локальный адрес. Авторизации нет, в сеть не выходит.

## 10. Этапы реализации

Порядок выбран так, чтобы самое рискованное проверялось первым. Если начать с канваса, несколько вечеров уйдёт на красивые карточки, а потом выяснится, что главное не работает.

| Этап | Что делаем | Готово, когда |
|---|---|---|
| **0. Разведка** | мини-MCP из одного инструмента, подключить к рабочей среде | Claude вызывает инструмент и возвращает ответ |
| **1. Ядро** | структура данных, чтение-запись файла, API, проверки, автокопии | через API создаётся карта с этапами и задачами и читается обратно |
| **2. MCP** | все инструменты из раздела 7 | Claude строит карту по описанию цели и закрывает задачи |
| **3. Интерфейс списком** | сайдбар, дерево задач, панель задачи, живое обновление | правки Claude видны в браузере без перезагрузки |
| **4. Канвас** | React Flow, ноды, стрелки, зум, миникарта, автораскладка | выглядит как референс, не тормозит на сотне нод |
| **5. Доводка** | экспорт в markdown, горячие клавиши, шаблоны карт | можно пользоваться каждый день без раздражения |

После этапа 2 инструмент уже рабочий, просто без картинки. Это точка, где стоит остановиться и проверить, пользуешься ли им на самом деле.

**Правило работы:** после каждого этапа — отчёт владельцу, проверка, и только с его явного разрешения переход к следующему. Без разрешения следующий этап не начинается.

## 11. Что входит в первую версию

Этапы 0–4.

- хранение карт в общей папке, одна карта — один файл
- создание и правка карт, этапов, задач, подзадач
- статусы, критерии приёмки, зависимости, заметки
- MCP со всеми инструментами раздела 7, включая «дай следующую задачу»
- сайдбар со списком карт и этапов, счётчики прогресса
- канвас с нодами, стрелками, зумом, миникартой и автораскладкой
- панель задачи с редактированием
- живое обновление страницы при правках агента
- тёмная тема
- одна активная карта за раз, остальные в архиве

## 12. Что пока не делаем

Каждый пункт по отдельности недорогой, вместе они превращают несколько вечеров в полгода.

- аккаунты и вход
- совместная работа нескольких людей, комментарии
- сроки, дедлайны, диаграмма Ганта
- мобильная версия и доступ с телефона
- публичные ссылки «показать другому»
- работа из сети, деплой на сервер — только локально
- интеграции с GitHub, Linear, Notion
- хранение карт в базе данных
- уведомления
- несколько карт одновременно на одном экране
- вложенность глубже четырёх уровней

## 13. Риски и что с ними делаем

| Риск | Решение |
|---|---|
| Рабочая среда не подключает локальный MCP — главная функция не работает | проверяем на этапе 0, до того как написана строчка приложения |
| Пользователь и агент правят одну задачу одновременно | у задачи номер версии; запись со старым номером отклоняется, сервер просит перечитать |
| Агент испортил файл карты | запись только через API с проверкой структуры; перед каждой — автокопия |
| Канвас тормозит на большой карте | рисуем только видимые ноды, на далёком зуме упрощаем карточки. Цель — 300 нод без лагов |
| Агент накрошит сотни мусорных подзадач | потолок в bulk_create — не больше 40 задач за вызов, четыре уровня глубины, в описании инструмента просьба дробить до объёма «полдня работы» |
| Карта устаревает, потому что её не обновляют | в инструкциях проекта правило: сессия начинается с get_next_task, заканчивается set_status и add_note |
| Проект заброшен после этапа 2, канвас не доделан | это допустимый исход: после этапа 2 инструмент рабочий. Решение принимается осознанно, а не по инерции |
